# Правила работы над игрой

## История изменений

- Не создавать копии версий игры в отдельных файлах (`version-1.html`, `version-2.html`, `index-backup.html` и подобных).
- Сохранять законченные изменения коммитами в локальном Git-репозитории этой папки.
- Перед коммитом проверять изменения и выполнять проверки, подходящие для задачи.
- В сообщении коммита кратко описывать, что изменилось и зачем.
- Предыдущие версии просматривать и восстанавливать из истории Git.
- Не переписывать существующую историю и не публиковать репозиторий без отдельного запроса пользователя.

Исходники игры — `src/`. Сборка `npm run build` создаёт `dist/index.html` и обновляет готовый `index.html` в корне. Не редактировать собранный HTML вручную. Корневой HTML, `dist/` и `.generated/` — результаты сборки и не коммитятся. Корневой файл остаётся на диске для привычного автономного запуска. Ассеты, их лицензии и инструменты сборки также хранятся в Git.

## Чистота репозитория

- Сохранять скачанные наборы ассетов целиком, включая пока неиспользуемые модели, форматы, превью и лицензии: они могут пригодиться для будущих доработок.
- Не удалять части исходных наборов ассетов при очистке без явного запроса пользователя.
- Не добавлять старые HTML-копии, дубли сгенерированных данных и временные скриншоты.
- Проверочные скриншоты и другие временные результаты сохранять вне репозитория.

## Каталог создаваемых 3D-моделей

- Вести карту моделей в `docs/models.md` и машинный каталог `assets/art/models.json`. После создания, изменения, экспорта или подключения своей 3D-модели обновлять её запись в обоих файлах.
- Сохранять стабильный ID, актуальный `.blend`, уже имеющиеся превью, референс, промпт/генератор, статус визуального согласования, игровой экспорт и место подключения в игре. Отличать картинки-референсы от настоящих 3D-моделей.
- Статистику геометрии привязывать к версии файла; после правок обновлять её или помечать устаревшей. Не объявлять модель готовой к игре только по числу полигонов: отдельно фиксировать экспорт, материалы и проверку в движке.
- Для ведения каталога и оценки модели не выполнять тяжёлые рендеры. Проверять через viewport, Workbench или лёгкое Eevee-превью; качественный долгий рендер — только по явной просьбе пользователя.

## Архитектура и документация

- Все экраны игры должны сохранять соотношение сторон 16:9. Игровая область вписывается целиком по центру окна без растяжения и обрезки; свободное место сверху/снизу или слева/справа заполняется сплошным чёрным цветом. Изменение размеров окна не должно менять пропорции игровой области.
- Новичок должен понимать исходники: читаемое форматирование, названия и комментарии к намерению и причинам решений.
- `domain/` не зависит от браузера и Babylon.js. Внешние слои меняют город только через команды публичного интерфейса.
- Соседние модули импортируют публичный `index.ts`, не внутренние файлы. `main.ts` соединяет модули.
- При изменении механики обновлять `docs/requirements.md`; при изменении архитектуры — `docs/architecture.md` и соответствующее решение в `docs/decisions.md`.
- Использовать `npm run check`; для изменений поведения или графики готовой игры — `npm run test:e2e`.
- Сохранять автономность сборки: без CDN, сетевой загрузки моделей и внешних ресурсов во время игры.

- Весь код приложения — TypeScript с `strict: true`. Не подавлять ошибки через `any` или `@ts-ignore`.
- Палитра HTML-интерфейса, шрифты и общие эффекты задаются только в `src/ui/theme.css`. Компоненты используют переменные, не копии цветов.
- `.js` в import-путях исходников — намеренная конвенция TypeScript; имена исходных файлов имеют `.ts`.

## Локальный редактор объектов

- Мастерская — отдельное Node.js-приложение `src/editor/`, запуск `npm run editor`. Её UI, Gizmos и полный каталог Kenney не должны попадать в автономную игру.
- Кнопка «Сохранить» по запросу владельца записывает `src/objects/templates.json`, создаёт локальный коммит только этого файла в `main` и пересобирает игру. Push автоматически не выполняется; чужие staged-файлы не включаются, Git hooks не обходятся.
- Единица сетки редактора соответствует клетке игры 1×1. Занимаемый участок задаётся связной маской до 4×4 с обязательной опорной клеткой; игровой домен проверяет всю маску. Общий масштаб геометрии независим от занимаемых клеток. Редактор занимает окно браузера; правило 16:9 относится к экранам самой игры.
- Тестировать запись и коммиты редактора в отдельном временном репозитории, не тестовыми моделями в рабочей `main`.
